Modulon Test Suite Documentation

1.1-rc1 Tests:

jit_1.mlon

Purpose:
  Tests JIT execution involving external symbol resolution, mutable global
  storage, recursion, and propagation of main()'s return code through the JIT.

Features tested:
  - #include <stdio.h>
  - Global mutable integer variables
  - Recursive functions
  - for loops
  - Function calls
  - Arithmetic
  - printf()
  - JIT execution of code that uses an external library function
  - JIT exit-code propagation

Program behavior:
  - Calculates fib(0) through fib(9)
  - Adds all ten Fibonacci values to the global counter
  - Prints the resulting sum
  - Returns 0 only when the sum is 88

Expected output:
  fib sum: 88

Pass condition:
  The program must print 88 and return exit status 0.
  Any other result returns exit status 1.


jit_2.mlon

Purpose:
  Tests JIT handling of read-only string data, multiple distinct external
  imports, strlen(), and match-expression code generation.

Features tested:
  - Global string variables
  - String literals
  - #include <string.h>
  - strlen()
  - match expressions
  - Inclusive range patterns (e.g. 0...199)
  - Wildcard/default match pattern (_)
  - Multiple external functions/imports
  - JIT execution and external symbol resolution

Program behavior:
  - Defines the string "modulon jit"
  - Classifies numeric codes into ranges
  - Calculates the length of the banner
  - Adds three classification results
  - Prints both the banner/length and classification total

Expected output:
  banner: modulon jit (len 11)
  classified total: 3

Pass condition:
  strlen(banner) must be 11 and the classification total must be 3.
  The program returns 0 when both conditions are true; otherwise 1.


match_1.mlon

Purpose:
  Tests statement-style pattern matching with several pattern forms and a
  guarded case.

Features tested:
  - match statements
  - Comma-separated discrete patterns
  - Inclusive range patterns
  - Guard conditions using if
  - Wildcard/default pattern (_)
  - Functions returning strings
  - String variables
  - String comparison with ==
  - Multiple return paths

Patterns tested:
  - 1, 2, 3, 4, 5 -> "weekday"
  - 6, 7 with weekend_bonus > 0 -> "bonus weekend"
  - 6, 7 -> "weekend"
  - 8...31 -> "out of range"
  - _ -> "invalid"

Test cases:
  - day 3, bonus 0 -> weekday
  - day 6, bonus 5 -> bonus weekend
  - day 7, bonus 0 -> weekend
  - day 15, bonus 0 -> out of range
  - day 0, bonus 0 -> invalid

Expected output:
  day 3: weekday
  day 6 (bonus): bonus weekend
  day 7 (no bonus): weekend
  day 15: out of range
  day 0: invalid

Pass condition:
  All five classifications must match their expected strings.
  The program returns 0 when they all match; otherwise 1.

Features tested:

  - Nested match expressions
  - Match expressions assigned to variables
  - Modulo arithmetic
  - for loops
  - Function return values produced by match
  - String values produced by match
  - Wildcard/default pattern (_)

  - fizz_value() classifies numbers using n % 15, n % 3, and n % 5
  - main() runs the classification from 1 through 15
  - Numeric codes are converted into Fizz/FizzBuzz/Buzz/number labels
  - All numeric codes are added to total

Expected output:
  The program prints one classification for each number from 1 through 15,
  followed by:
  total: 11

Pass condition:
  The final total must be 11.
  The program returns 0 when it is; otherwise 1.


memory_1.mlon

Purpose:
  Tests struct layout and pointer-based mutation of a local variable.

Features tested:
  - struct definitions
  - Struct fields
  - Struct pointers
  - Address-of operator (&)
  - Pointer dereference (*)
  - Arrow member access (->)
  - Pointer parameters
  - Mutating a struct through a pointer
  - Observing mutations through both the original variable and pointer

Program behavior:
  - Creates Point {x = 1, y = 2}
  - Takes the address of the struct
  - translate() adds 4 to x and 5 to y
  - Reads the result directly and through the pointer

Expected output:
  point: (5, 7)
  via pointer: (5, 7)

Pass condition:
  Both the original struct and pointer view must contain x = 5 and y = 7.
  The program returns 0 when all checks pass; otherwise 1.


memory_2.mlon

Purpose:
  Tests heap allocation, indexed pointer access, freeing memory, and a
  mutable global accumulator shared between function calls.

Features tested:
  - #include <stdlib.h>
  - malloc()
  - free()
  - sizeof()
  - Pointer variables
  - Pointer indexing with []
  - Passing pointers to functions
  - Mutable global variables
  - for loops
  - Integer multiplication
  - Reading heap data after writing it

Program behavior:
  - Allocates space for five integers
  - Stores 0, 1, 4, 9, and 16 through a helper function
  - The helper increments the global calls counter every time it writes
  - Reads all five values back and adds them together
  - Frees the allocated buffer

Expected output:
  sum of squares: 30
  record calls: 5

Pass condition:
  The sum must be 30 and the global call counter must be 5.
  The program returns 0 when both checks pass; otherwise 1.

string_2.mlon

Purpose:
  Tests dynamic string construction on the heap and verifies that the
  resulting string is independent from the source variables.

Features tested:
  - string variables
  - malloc()
  - strlen()
  - strcpy()
  - strcat()
  - strcmp()
  - free()
  - String casts
  - Heap-allocated strings
  - Passing strings to functions
  - Concatenating multiple strings

Program behavior:
  - join() allocates enough memory for two strings and a separator
  - It copies the first string and appends the separator and second string
  - main() creates "hello, modulon"
  - The original source variables are then changed to "changed"
  - The test checks that the dynamically created greeting remains unchanged

Expected output:
  hello, modulon

Pass condition:
  greeting must still equal "hello, modulon" after the source variables
  change, and its length must be 14.
  The allocated greeting is freed before successful exit.
  The program returns 0 when both checks pass; otherwise 1.

types_2.mlon

Purpose:
  Tests struct type identity, sizeof() calculations, and unsigned 8-bit
  integer wraparound.

Features tested:
  - struct definitions
  - Struct variables
  - typeof() on struct values
  - Struct type identity
  - sizeof(struct)
  - sizeof(int)
  - uint8_t
  - Unsigned overflow/wraparound
  - for loops

Program behavior:
  - Creates two Pair structs with the same type
  - Starts a uint8_t counter at 250
  - Increments it ten times
  - Since uint8_t wraps after 255, the final value is 4
  - Compares the struct size with the combined size of its two int fields

Expected output:
  sizeof(struct Pair): <implementation-dependent size>
  sizeof(int): <implementation-dependent size>
  wrapped counter: 4

Pass condition:
  typeof(p1) must equal typeof(p2), sizeof(struct Pair) must equal
  2 * sizeof(int), and the uint8_t counter must wrap to 4.
  The program returns 0 when all checks pass; otherwise 1.


Beta tests:

1.1-beta5.mlon

Purpose:
  Integration test combining pattern matching and strings.

Features tested:
  - Functions
  - int parameters and return values
  - match statements
  - Exact integer match cases
  - default match case
  - string variables
  - String literals
  - Multiple function calls
  - Arithmetic on returned values

Match cases:
  - 200 -> 0
  - 404 -> 1
  - 500 -> 2
  - default -> -1

Program behavior:
  - Creates a string banner: "Modulon v1.1-beta test runner"
  - Calls eval_code() for 200, 404, and 999
  - Stores the three results in res1, res2, and res3
  - Adds them into sum

Important note:
  This beta test currently does not print its result and does not explicitly
  return a pass/fail status from main(). Therefore, the source itself does
  not provide an explicit runtime assertion like the 1.1-rc1 tests do.

Expected calculated values:
  res1 = 0
  res2 = 1
  res3 = -1
  sum  = 0

Interpretation:
  If used as an integration/compile test, successful compilation and
  execution are the primary checks. To turn it into a self-checking runtime
  test, main() would need to print or assert the calculated values and/or
  return a nonzero status on failure.


Summary:

The current test suite covers:

  JIT:
    - External symbol resolution
    - GOT/thunk handling
    - Read-only string data
    - Mutable globals
    - Recursion
    - JIT exit-code propagation

  Pattern matching:
    - Exact patterns
    - Comma-separated patterns
    - Inclusive ranges
    - Guards
    - Wildcards/defaults
    - Match expressions
    - Nested match expressions

  Memory:
    - Struct layout
    - Struct pointers
    - Address-of and dereference
    - -> member access
    - Heap allocation
    - Heap indexing
    - malloc/free
    - Mutable global state

  Strings:
    - String variables and literals
    - String indexing
    - strlen()
    - strcmp()
    - strcpy()
    - strcat()
    - Heap-allocated strings
    - String independence after copying

  Types:
    - typeof()
    - Primitive type literals
    - Explicit casts
    - Numeric narrowing/conversion
    - Struct type identity
    - sizeof()
    - uint8_t overflow/wraparound

  General language/runtime behavior:
    - Functions
    - Parameters and return values
    - Variables
    - Loops
    - Arithmetic
    - Logical operators
    - Character literals
    - C-style headers/library calls
